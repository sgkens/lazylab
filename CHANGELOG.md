Notable changes to lazylab, newest first. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/) once 1.0 is released. Commit-level detail is in the git history (Conventional Commits).

## [Unreleased]

Version in `package.json`: 0.1.0. No release has been tagged yet.

### Added

- **Notes and tasks:** a Notes view for personal notes and tasks outside GitLab, with tags, Markdown bodies, a done checkbox, filters and a comment log, encrypted in the vault with a separate demo list. **Migrate to GitLab** creates an issue from the note and its comments, then marks the note migrated or deletes it. **Export .zip** downloads every note as Markdown with YAML front matter (no new dependency). `lazy note add/list/show/done/reopen` and the MCP tools `list_notes`, `get_note`, `add_note` and `set_note_status` use the same storage.
- **Docs polish:** aligned header and content columns, responsive scroll-aware contents, build-time heading links, prominent source edit links, reading progress, copy controls, thin scrollbars and reduced-motion-aware transitions. Locally bundled Hawk/Pagefind search uses the TypeFlow animation driver and Logcad diagnostics.
- **Testing readiness:** GitLab CI checks types, tests, the app build and CLI compilation before docs publishing; branch pushes with an open MR use the MR pipeline. Added a live acceptance-testing guide with known limits and failure-reporting instructions.
- **BugKB integration:** optional `LAZYLAB_BUGKB_URL` adds bounded searches for prior fixes to task briefings, with trust, environment and evidence. Four MCP tools and `lazy kb search/show/add/confirm` support explicit verified findings. The independent BugKB retains its validation, duplicate refusal and trust rules; offline searches leave the rest of the briefing usable.
- **Agent briefings and handoffs:** `get_task_briefing` gathers issue/MR context, acceptance checklists, related MRs, bounded patches and CI failures in one read. `save_handoff` and `list_handoffs` provide encrypted task history with agent identity, verification reports and next steps. `lazy brief` and `lazy handoff` expose the same workflow in the terminal.
- **Brand** (`brand/`): the flask-and-zz mark, logos for light and dark backgrounds, one-colour marks, favicon, home-screen icon, 1280 × 640 link preview, colour tokens and a brand guide page, generated by [brandkit](https://gitlab.com/sgkens/brandkit) from one reference SVG. The app header, sign-in screen, favicon, docs site and README use it. The generator started in this repository as `brandkit/` and now lives in its own.
- **Docs:** landing page with "choose your path" cards, an FAQ and troubleshooting page, a Brand page, link previews (`og:*`) when `DOCS_SITE_URL` is set, and a favicon.
- **Repository:** `CONTRIBUTING.md`, `SECURITY.md` and this changelog.
- **Local environment** (ENV-1, ENV-2): `lazy env` lists the CI/CD variables that apply to a project, `lazy env pull` writes them to a `.env` file, and `lazy run -- <cmd>` passes them to a command. Follows GitLab's precedence and environment-scope rules; hidden values come from the vault.
- **Agent tokens with secret access:** a "Can read secrets" option at creation. Only such tokens see and call the MCP tool `get_env`; each call is journaled.
- **`lazy` command line** (CLI-1, CLI-2): `inbox`, `ci`, `ci watch`, `job log`, `retry`, `mr create` and `push`, which follows the new pipeline and asks lazylab to notify you. Finds the project from the git remote.
- **MCP tool `get_pipeline`**, and `retry_job` returns the pipeline of the new job.
- **Token expiry** (ENV-4): warnings 14, 7, 3 and 1 days before a personal, project, group or deploy token expires; rotate a profile's personal access token from the vault.
- **MCP server** at `/mcp` for Claude Code, Codex and other MCP clients, with setup commands shown after creating an agent token.
- **CI failure triage:** the failing section of a job log with error line, exit code, failure reason and a "likely passes on retry" hint; run pipelines with declared variables; retry jobs.
- **Watches and notifications:** watch pipelines, jobs and merge requests; push to ntfy, Gotify and Slack, Discord or JSON webhooks; failure notifications name the failing job.
- **Inbox:** merge requests, issues and To-Dos across member projects, grouped by who has to act next, as the default view.
- **Agent skill** for Claude Code, Codex and Antigravity.
- **Documentation site** (Eleventy), published with GitLab Pages; MIT licence.
- Initial import: sign-in with a one-time setup code, encrypted vault, TLS options and the GitLab UI for work items, merge requests, pipelines, releases and project settings.

### Changed

- **Cache engine:** the GitLab response cache uses `bun:sqlite` in WAL mode instead of sql.js. Writes are single rows instead of a full database export, and only recently used entries stay in memory. Existing cache files open without conversion. The `sql.js` dependency is gone.
- **Bounded cache journal:** the journal file rotates at 5 MiB with one previous file kept, and journal rows in the database are pruned to the newest 10,000 and the last 7 days (`LAZYLAB_JOURNAL_MAX_BYTES`, `LAZYLAB_JOURNAL_KEEP_ROWS`, `LAZYLAB_JOURNAL_KEEP_DAYS`). Re-caching an unchanged GitLab response only extends its TTL and is not journaled.
- **Cache retention:** a sweep at start and every 10 minutes deletes rows expired for more than 24 hours and the oldest rows beyond 5,000 rows or 128 MiB (`LAZYLAB_CACHE_STALE_HOURS`, `LAZYLAB_CACHE_MAX_ROWS`, `LAZYLAB_CACHE_MAX_MB`). Expired rows of projects you are no longer a member of are deleted at the next project list refresh. Purged rows are overwritten on disk.

### Fixed

- CI/CD variables are read from every page; only the first 20 were read before.
- Demo group variables were shown for every group.
- No expiry warnings for demo sample tokens.
- The work item drawer refreshes from GitLab after subtask changes.
- Masked CI variable values are no longer sent to the browser in lists or the live update stream.
- Failed GitLab list reads are reported instead of returning empty lists.
- Badge URLs are built from the project's own GitLab instance.
- Agents read single work items and merge requests directly instead of searching the first 50.
- The Docker image ships `skills/` for `/api/agent/skill.md`.
- Every UI entry point reaches a working action; live writes no longer fall back to made-up data.
- Cross-project views fan out per project instead of calling non-existent global endpoints.
- Cache entries expire after their TTL.
